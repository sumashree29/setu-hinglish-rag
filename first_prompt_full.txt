## 1. VERIFIED AUDIT FINDINGS (as of `f8406a4`)

### A. Blocking scientific defects

**A1 — The controller behind the headline result is trained on a stale, mismatched log.**
`data/logs/trajectories.jsonl` contains 692 rows spanning only **76 unique query strings**, all
from the retired 75-query pilot set. `scripts/compare_setu_v1_v2_scaled.py` evaluates SETU v2 on
**314** queries from `data/processed/queries_v3_final.json`. For ~238 of the 314 evaluation
queries, the 5-fold "out-of-fold" filter is a no-op, because those queries never appear in the
trajectory log at all. The reported policy is therefore trained on a 4× smaller, different
distribution than the one it is evaluated on.

**A2 — The STOP arm has never been trained; its value is a structural zero.**
Action counts in the trajectory log: `LAG 232, LQP 231, CAEP 229, STOP 0`. `log_trajectory()` is
only called for operator invocations. Consequently `b["STOP"]` stays the zero vector,
`theta_STOP = A⁻¹b = 0`, and with `alpha=0.0` the UCB score of STOP is *exactly* `0.0` for every
context. STOP is selected whenever every operator's predicted Δconfidence is negative. This may
still be a valid and interesting result, but it cannot be described as "the controller learned
when to stop." It is "STOP is the zero-valued default action, and operators are predicted to have
negative value on most queries."

**A3 — The deployed policy is not LinUCB.**
`scripts/compare_setu_v1_v2_scaled.py` line ~117: `LinUCBController(context_dim=7, alpha=0.0)`.
With `alpha=0`, the exploration bonus `alpha * sqrt(xᵀA⁻¹x)` vanishes and the policy is a greedy
linear reward-argmax (ridge regression). Evaluating greedily is defensible; calling the
*evaluated* policy "LinUCB" without stating `alpha=0` is not.

**A4 — `mean_steps` conflates learned stopping with forced termination.**
`setu/controller/setu_bandit.py`, in `setu_v2_run`:
```python
if action == "STOP" or (action in tried and tried[action] == 1.0):
    ...
    operator_sequence.append("STOP")
    break
```
Selecting an already-used action forces termination and is *recorded as a STOP*. The reported
`mean_steps = 1.197` therefore mixes three distinct stop causes. There is currently no way to
tell them apart from any artifact in the repo.

**A5 — Step counting is asymmetric between v1 and v2.**
v2: `len([o for o in ops if o != "STOP"])`, measured. v1: `4.00`, asserted by construction and
never measured in the script (`v1_metrics` has no `mean_steps` key). The claimed "70.1% fewer
steps" compares a measured quantity against an assumed constant.

**A6 — The fold split leaks on duplicate query text.**
The OOF filter uses `set(q_by_id[qid]["text"] for qid in test_qids)`. There are 314 queries but
only **310 unique texts**, so 4 queries can appear in both the training trajectories and the
held-out fold. Split on `query_id`, not text.

**A7 — Table IV and Table V are computed on different datasets.**
`outputs/tables/operator_ablation.json` is `n_total_queries: 75`, RAW MRR `0.8666`, RAW nDCG@10
`0.8960`. `outputs/tables/setu_v1_v2_comparison_scaled.json` is `n_total_queries: 314`, RAW MRR
`0.8526`, RAW nDCG@10 `0.8858`. The correct 314-query ablation exists at
`results/tables/scaled_operator_ablation_v3.json`. The stale 75-query file must not reach the
paper.

**A8 — The extended-baselines table contains citations that do not check out.**
`results/tables/extended_baselines.md` attributes ColBERT-X to "Khattab & Zaharia, 2020"
(that paper is ColBERT; ColBERT-X is Nair et al., ECIR 2022), and attributes MIRACL-Hindi numbers
to "Formal et al., SIGIR 2022, Table 2" (MIRACL is Zhang et al., TACL 2023; the SPLADE papers do
not report MIRACL Hindi). All values are vague ranges (`~0.78–0.82`). Under IEEE author-ethics
rules this is a fabrication risk, not a formatting issue.

**A9 — 76% of the evaluation set is unreviewed machine-generated text.**
`data/processed/queries_v3_final.json`: 239 of 314 queries carry
`"review_status": "auto_generated_v3_paraphrased"`; none is marked verified. The planned
three-person human review never happened. This is the single easiest thing for a reviewer to
reject the paper on.

**A10 — Latency measurement is not defensible as reported.**
In `compare_setu_v1_v2_scaled.py`: no warm-up, a single run per query, mean only (no median, SD,
or CI), RAW is never timed at all inside this script, and v1 and v2 are timed in different loops
under different cache states. No hardware, OS, thread count, or BLAS configuration is recorded
anywhere in the repo.

**A11 — Reward contains no intervention cost.**
`reward = confidence_after - confidence_before` (a margin proxy), and STOP is hardcoded to
`reward=0.0`. Nothing in the objective trades quality against steps or latency. Step reduction is
therefore an *emergent consequence* of operators having negative predicted value — not something
the controller was optimizing. Do not write "the controller balances quality against cost."

**A12 — No seeding in the comparison script.**
`scripts/run_statistical_tests_h1_h10_scaled.py` sets `np.random.seed(42)`.
`scripts/compare_setu_v1_v2_scaled.py` sets no seed, and `EpsilonGreedyController` calls the
bare `random` module.

**A13 — Model loading is not reproducible.**
`SentenceTransformer("BAAI/bge-m3", local_files_only=True)` — requires a pre-populated local
cache and pins no HF revision. A clean machine cannot reproduce the results.

**A14 — Measurement validity of CMI is unestablished.**
`setu/diagnosis/lid_entropy.py` uses a hand-rolled lexicon/heuristic tagger, not IndicLID. CMI
feeds both H1 (null result) and the controller's context vector. A null result from an
unvalidated instrument is the weakest possible null result.

**A15 — LAG's classifier is circular.**
LAG labels were derived from a deterministic heuristic rule (entity corruption + CMI threshold),
then a LightGBM model was fit on those labels, reaching ~100% training accuracy. The model
re-derives the rule; it does not generalize. Either report it as the rule it is, or disclose the
circularity explicitly.
